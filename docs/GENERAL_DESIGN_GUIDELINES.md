# 资料型网站通用设计规范

## 1. 设计方向

整体定位为：

> 清晰、克制、有阅读感的资料工作台。

设计应强调内容检索、详情阅读和信息关联，而不是追求强烈装饰或营销感。

基本原则：

- 内容优先，装饰服务于信息层级；
- 桌面端适合高密度检索，移动端优先阅读；
- 保持安静、耐看的视觉环境；
- 用边线、留白和字体建立层次；
- 避免大量渐变、玻璃拟态、悬浮卡片和高饱和色；
- 同一页面只设置一个最强视觉重点。

## 2. 色彩系统

建议建立以下基础色彩角色：

| 角色 | 示例色值 | 用途 |
|---|---:|---|
| 页面背景 | `#f2f3ed` | 全局底色 |
| 内容背景 | `#fafaf6` | 正文、卡片、弹窗 |
| 深层背景 | `#e8ebe5` | 标签、表格标题和轻微层次 |
| 主文字 | `#17313a` | 标题和正文 |
| 次要文字 | `#506066` | 说明、标签和元数据 |
| 主强调色 | `#c64b3c` | 当前项、主操作和重点状态 |
| 交互色 | `#2f6b61` | 链接和可点击对象 |
| 辅助强调色 | `#b38a48` | 分类、眉题和辅助状态 |
| 普通边框 | `#d8ddd8` | 卡片和分区边界 |
| 强边框 | `#bbc5c1` | 栏目边界和重要分隔线 |

使用规则：

- 背景与正文使用低饱和颜色；
- 主强调色只用于当前选择和关键动作；
- 交互色应保持统一，不随组件任意变化；
- 辅助色用于层级提示，不能与主强调色争夺注意力；
- 状态不能只依靠颜色，还应配合边框、文字或图形变化。

## 3. 字体系统

至少划分三类字体角色。

### 展示字体

用于品牌名称、页面主标题、内容名称和章节标题。字体可以具有一定个性，但不能影响长标题阅读。

### 正文字体

用于表单、按钮、说明文字、数据字段和常规正文。优先选择清晰的系统无衬线字体。

### 数据字体

使用等宽字体，用于编号、版本号、数量、时间、技术字段和小型英文栏目标签。

推荐字体栈：

```css
:root {
  --display: serif;
  --body: system-ui, sans-serif;
  --mono: ui-monospace, monospace;
}
```

## 4. 字号层级

| 层级 | 建议字号 |
|---|---:|
| 页面主标题 | `28–42px` |
| 一级栏目标题 | `22–26px` |
| 二级栏目标题 | `18–22px` |
| 卡片标题 | `14–17px` |
| 正文 | `15–18px` |
| 表单与按钮 | `12–14px` |
| 辅助信息 | `10–12px` |
| 数据眉题 | `9–10px` |

长文本建议：

```css
.prose {
  font-size: 17px;
  line-height: 1.8;
}
```

标题可适当增加字距，正文避免过宽字距。

## 5. 页面布局

资料型页面推荐采用三栏结构：

```text
┌──────────────────── 顶部栏 ────────────────────┐
│ 品牌与导航                  状态与辅助入口       │
├────────────┬────────────────────┬──────────────┤
│ 检索与筛选 │      主要内容       │ 关联与补充信息 │
└────────────┴────────────────────┴──────────────┘
```

推荐尺寸：

```css
.workbench {
  display: grid;
  grid-template-columns:
    minmax(270px, 320px)
    minmax(530px, 1fr)
    minmax(270px, 320px);
  max-width: 1800px;
  margin: 0 auto;
}
```

布局规则：

- 中栏始终拥有最多空间；
- 左栏负责查找和筛选；
- 右栏负责关系、上下文和补充资料；
- 最大页面宽度可设置为 `1600–1800px`；
- 栏目之间使用细边线分隔；
- 不为每个区块都添加阴影；
- 正文区域应有足够的内边距。

内容不需要三栏时，可以采用“筛选栏 + 主内容”或“主内容 + 上下文侧栏”。

## 6. 间距系统

建议以 `4px` 为基础单位：

| 间距 | 用途 |
|---:|---|
| `4px` | 极小间距 |
| `8px` | 紧密内容 |
| `12px` | 组件内部 |
| `16px` | 常规间距 |
| `24px` | 区块间距 |
| `32px` | 大区块间距 |
| `48px` | 页面级留白 |

原则：

- 同一组件内部使用较小间距；
- 不同信息组之间使用明显更大的间距；
- 不依靠连续空行制造层级；
- 标题与所属内容的距离，应小于标题与上一组内容的距离。

## 7. 边框与形状

- 普通边框使用 `1px solid`；
- 当前项可以使用更强边框或侧边色条；
- 默认卡片采用小圆角或方角；
- 不要所有组件都使用大圆角；
- 胶囊形状只用于标签、状态和短小实体；
- 图标容器可使用小方框形成稳定的视觉锚点；
- 阴影只用于弹窗、浮层和明显高于页面的组件。

示例：

```css
:root {
  --border: 1px solid #d8ddd8;
  --border-strong: 1px solid #bbc5c1;
  --shadow-overlay: 0 24px 80px rgba(23, 49, 58, 0.24);
}
```

## 8. 信息标题结构

栏目可以统一使用：

```text
辅助眉题
主要标题
────────────
内容
```

辅助眉题建议：

- `9–10px`；
- 等宽字体；
- 大写或固定格式；
- 较宽字距；
- 使用辅助色；
- 只负责分类和节奏，不承载主要信息。

主要标题应直接表达访问者正在查看的内容。

## 9. 检索与筛选

检索区通常包括：

- 一个明显的主搜索框；
- 数量有限的常用筛选条件；
- 主搜索按钮；
- 清除条件入口；
- 当前结果数量；
- 分页或连续加载状态。

规范：

- 输入框高度不低于 `36px`；
- 移动端触控目标尽量达到 `44px`；
- 标签放在输入框上方，不只依赖占位文字；
- 筛选条件按使用频率排序；
- 次要筛选可以折叠；
- 加载时降低结果区透明度并阻止重复操作；
- 无结果时说明原因，并提供清除条件的方式。

## 10. 列表卡片

列表卡片应保持紧凑：

```text
名称
主要属性                 次要属性
```

交互状态：

- 默认：浅色背景和普通边框；
- 悬停：交互色边框，轻微位移；
- 当前：强调色背景或侧边色条；
- 禁用：降低透明度；
- 加载：整体变淡且不可点击。

推荐动效：

```css
.result-card {
  transition:
    border-color 160ms ease,
    background 160ms ease,
    transform 160ms ease;
}

.result-card:hover {
  transform: translateX(2px);
}
```

悬停位移不应超过 `2px`，避免页面显得躁动。

## 11. 详情页面

详情区域建议按照以下顺序：

1. 名称和状态；
2. 关键属性；
3. 主要正文；
4. 条件、组成或明细；
5. 关联内容；
6. 来源或技术资料。

规则：

- 首屏只展示最重要的信息；
- 技术字段放在页面下部或折叠区域；
- 使用定义列表展示固定属性；
- 属性较多时分组，不使用一张无限增长的大表格；
- 缺失内容明确显示“暂无记录”，不能生成猜测性文字；
- 重复和冲突资料应保留，但避免干扰主要阅读。

## 12. 标签页

标签页适合切换同一对象的不同内容类型。

规范：

- 当前标签使用强调色文字和下边框；
- 非当前标签使用次要文字色；
- 标签过多时允许横向滚动；
- 空标签可以显示小型状态标记；
- 不使用整块高饱和背景表示选中；
- 必须设置正确的键盘焦点和 ARIA 属性。

## 13. 标签与状态

标签应有明确语义，而不是纯装饰。

推荐类型：

- 普通对象：交互色；
- 警告或重点：主强调色；
- 分类与辅助信息：辅助色；
- 未确认信息：虚线边框；
- 无法解析信息：降低饱和度并显示文字说明。

胶囊标签只适合短内容。长名称应使用普通文本链接或卡片。

## 14. 关系展示

少量关系适合使用纵向关系链：

```text
上游内容
    │
当前内容
    │
下游内容
```

较多关系应使用分组列表：

```text
来源
用途
相关内容
相似内容
```

规范：

- 当前节点具有最强视觉强调；
- 可点击节点使用统一交互色；
- 节点文字过长时截断，并提供完整标题；
- 关系类型应通过位置或文字表达；
- 不使用复杂网络图展示本可用列表表达的信息；
- 只有关系数量和分支足够复杂时，才使用真正的图结构。

## 15. 空状态与错误状态

空状态应包含：

- 简单图形或文字标记；
- 当前没有内容的说明；
- 用户下一步可以做什么。

示例：

```text
暂无符合条件的记录
请调整筛选条件或清除当前搜索
```

错误状态应说明：

- 发生了什么；
- 是否可以重试；
- 如何返回安全页面。

不要只显示错误编号。

## 16. 动效

动效应集中在少数关键位置：

- 页面详情载入；
- 弹窗出现；
- 侧栏展开；
- 列表项悬停；
- 标签页切换。

| 类型 | 建议时长 |
|---|---:|
| 悬停反馈 | `120–160ms` |
| 标签切换 | `150–200ms` |
| 弹窗进入 | `180–220ms` |
| 抽屉展开 | `200–260ms` |
| 页面内容进入 | `350–500ms` |

进入动画的位移建议不超过 `8px`。

必须支持减少动画设置：

```css
@media (prefers-reduced-motion: reduce) {
  *,
  *::before,
  *::after {
    scroll-behavior: auto !important;
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
  }
}
```

## 17. 响应式设计

推荐断点：

```css
@media (max-width: 1250px) { }
@media (max-width: 980px) { }
@media (max-width: 620px) { }
```

### 大屏缩窄

- 缩小侧栏宽度；
- 减少正文左右内边距；
- 多列属性允许换行。

### 平板与移动端

- 正文成为主页面；
- 左右侧栏改成抽屉或底部面板；
- 保留固定的检索和上下文入口；
- 不把三栏简单纵向堆叠；
- 表格优先转换为卡片或横向滚动；
- 双栏内容改为单栏。

### 小屏手机

- 主标题适当缩小；
- 属性布局改成两列或一列；
- 按钮保证触控尺寸；
- 隐藏非必要状态文字；
- 弹窗宽度不超过视口减 `32px`。

## 18. 可访问性

最低要求：

- 使用语义化的 `header`、`main`、`nav`、`aside`、`section`；
- 提供“跳到正文”链接；
- 所有交互元素支持键盘操作；
- 使用明显的 `focus-visible` 描边；
- 表单标签不能只靠占位文字；
- 动态更新区域使用 `aria-live`；
- 标签页、弹窗和抽屉使用正确的 ARIA 状态；
- 颜色对比度满足正常阅读；
- 页面最低支持 `320px` 宽度；
- 尊重减少动画设置；
- 图标按钮必须提供可读的 `aria-label`。

## 19. 文案风格

界面文案应该：

- 简短、直接；
- 使用用户认识的名称；
- 一个动作始终使用同一个动词；
- 不暴露实现层术语；
- 空状态告诉用户下一步；
- 错误信息说明恢复方式；
- 不在普通页面大量使用宣传语。

例如：

- 使用“清除条件”，不要使用“重置查询参数”；
- 使用“暂无记录”，不要使用“返回数据为空”；
- 使用“查看详情”，不要使用“打开数据对象”。

## 20. 应避免的设计倾向

- 每个区块都做成悬浮圆角卡片；
- 大面积渐变和玻璃背景；
- 同一页面出现过多强调色；
- 为装饰而添加无意义英文；
- 使用大量图标替代清晰文字；
- 动效过多、位移过大；
- 移动端只是桌面布局的机械堆叠；
- 用颜色作为唯一状态提示；
- 首屏展示大量不重要的统计数字；
- 把技术字段放在主要信息之前；
- 为了“高级感”牺牲文本对比度和可读性。

## 21. 总结

这套规范适合资料库、知识库、档案站、目录网站、内容检索工具和管理型页面。

无论具体项目采用什么视觉主题，都应维持四项稳定原则：

> 内容优先、层级清楚、交互一致、移动端可用。
