# NPC／Boss 战斗属性解析参考

本文记录从现有 `mb` 资料中已经交叉验证的 NPC／Boss 战斗属性、附加状态和
机制配置。字段序号均从 `1` 开始。未列出的 `cha_fight` 字段仍然保持待确认，
不得仅凭数值大小命名。

## 基础关联链

NPC 和 Boss 的核心资料链为：

```text
mb/object/cha_list.txt
  第 2 字段：角色记录 ID
  第 5 字段：战斗属性 ID
  第 6 字段：外观 ID
  第 14 字段：附加状态组 ID 列表（`*` 分隔）
  第 19 字段：掉落组 ID 列表（`*` 分隔，开头的 `0` 是空值）
        │
        ├── 第 5 字段 → mb/object/cha_fight.txt 第 1 字段
        ├── 第 14 字段 → mb/skill/state_group.txt 第 2 字段
        └── 第 19 字段 → 对应掉落组编号空间
```

状态必须继续经过一跳：

```text
cha_list 状态组 ID
  → state_group.txt 第 2 字段
  → state_group.txt 第 4 字段中的实际状态数据 ID
  → state_data.txt 第 2 字段
  → state_data.txt 第 9 字段的属性修改串
```

禁止把 `cha_list` 第 14 字段直接连接到 `state_data.txt`。

## 状态属性串

`state_data.txt` 第 9 字段按三元组重复：

```text
修改模式 * 属性 ID * 数值
```

当前样本已确认：

- 修改模式 `0`：固定数值修改；
- 修改模式 `1`：百分比属性，资料整数除以 `100` 后为页面百分数；
- 多个百分比来源先相加，再作用于对应的 `cha_fight` 基础值；
- 负数表示降低，不得丢失符号。

龟丞相的“葬龙渊BOSS2”状态组为 `27145`，它指向实际状态数据 `27641`。
状态数据中的属性编号已经确认如下：

| 属性 ID | 含义 | 示例原始值 | 页面显示 |
| ---: | --- | ---: | ---: |
| 15 | 物理防御百分比 | `7500` | `+75%` |
| 19 | 物理会心伤害上限 | `3000000` | `+30,000%` |
| 20 | 法术会心伤害上限 | `3000000` | `+30,000%` |
| 29 | 法术抗性百分比 | `7500` | `+75%` |
| 32 | 幸运一击伤害减免 | `50000` | `+500%` |
| 39 | 最终防御效果 | `50000` | `+500%` |
| 45 | 忽略物理防御 | `2400000` | `+2,400,000` |
| 46 | 忽略法术抗性 | `800000` | `+800,000` |
| 68 | 会心伤害减免 | `8000000` | `+80,000%` |
| 70 | 受到怪物伤害修正 | `-9000` | `-90%` |

只应用“葬龙渊BOSS2”的 `+75%` 防御和法抗时：

```text
物理防御 = 4,806,000 × (1 + 0.75) = 8,410,500
法术抗性 = 1,200,000 × (1 + 0.75) = 2,100,000
```

## 编号空间与碰撞

`state_group` 和 `state_data` 是不同编号空间。相同数字不代表同一条状态。

已确认的碰撞示例：

| 编号 | `state_group.txt` | `state_data.txt` |
| ---: | --- | --- |
| `27477` | 霸体获取5，实际指向状态数据 `27984` | 九天劫后章boss1 |

龟丞相的 `cha_list` 第 14 字段包含 `27477`，这里必须解释成状态组“霸体获取5”，
不能直接命中状态数据“九天劫后章boss1”。如果错误地把两者都算入，物防和法抗
会被错误叠加 `+65%`：

```text
4,806,000 × (1 + 0.75 + 0.65) = 11,534,400
1,200,000 × (1 + 0.75 + 0.65) = 2,880,000
```

这两个结果虽然能与旧页面显示完全对上，但属于编号空间串用造成的假闭环，不能
作为正确解析保留。

## 龟丞相机制样例

龟丞相 `cha_list` 第 14 字段的状态组列表为：

```text
2720*53850*53849*53814*27145*53865*53866*53867*53868*53861*27477
```

已确认含义：

| 状态组 ID | 含义 |
| ---: | --- |
| `2720` | Boss 抵抗不良状态。 |
| `53850` | 选招1：攻击 2 次后释放 1 次龟遁术。 |
| `53849` | 深海护盾，大幅降低自身所受伤害。 |
| `53814` | 免疫水龙卷。 |
| `27145` | 葬龙渊BOSS2数值状态。 |
| `53865` | 锁血 80%。 |
| `53866` | 锁血 60%。 |
| `53867` | 锁血 40%。 |
| `53868` | 锁血 20%。 |
| `53861` | 免疫水龙卷异常。 |
| `27477` | 霸体获取5。 |

四条锁血状态分别指向同编号 `state_data` 记录；其第 5 字段保存阈值
`80 / 60 / 40 / 20`。状态组还关联无敌状态 `53869`，说明锁血阶段并非普通
生命提示，而是实际的阶段保护机制。

龟丞相 `cha_list` 第 19 字段为：

```text
0*9549*9559
```

去掉开头空值后，实际掉落组为 `9549` 和 `9559`。掉落组、状态组、状态数据、
技能和角色记录均须保留各自编号空间，不得只按数字跨表匹配。

## 新增解析规则的验证要求

后续补充字段或属性 ID 时必须同时满足：

1. 至少一个原始资料链能够完整走通；
2. 至少一个游戏内或页面上的已知数值可以复算；
3. 检查目标编号在相邻编号空间是否发生碰撞；
4. 百分比、固定值和负数修正分别测试；
5. 推测字段必须标记为待确认，不进入正式页面文案。
