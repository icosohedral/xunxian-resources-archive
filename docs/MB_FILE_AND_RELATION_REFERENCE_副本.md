# MB 文件含义与关联关系参考

本文汇总当前项目已经整理、解析或交叉验证过的 `original_data/mb/` 文件。
它不是对 `mb` 中全部文件的最终逆向结果；未在本文列出的文件仍保留在原始资料
清单中，不能据此认定为无用。

本文的字段序号均从 **1** 开始。字段状态使用以下口径：

- **确认**：有文件表头、`index_list.txt` 官方表名或稳定跨表关系支持；
- **高可信**：有多个样本和目标存在性支持，但尚缺正式字段名；
- **推测**：仅能说明当前最可能的用途，不进入正式事实文案；
- **未知**：只保留原值，不强行命名。

更细的字段证据见 [`../schemas/field_dictionary.md`](../schemas/field_dictionary.md)，
道具使用类型见 [`ITEM_USE_TYPES.md`](ITEM_USE_TYPES.md)，NPC／Boss 数值规则见
[`NPC_BATTLE_ATTRIBUTE_PARSING.md`](NPC_BATTLE_ATTRIBUTE_PARSING.md)。

### `original_data/index_list.txt`

这是 `mb` 资源的总索引，不在 `mb/` 子目录内。它为大量表提供官方备注、逻辑
文件名、索引列、起始行、列类型和加载范围。加载范围原注释为：`0` 服务端与
客户端都加载、`1` 服务端、`2` 客户端、`3` 两端通常都不加载但程序可能临时
读取。本文写“官方索引名称”时，依据的就是这份文件。

索引只能确认表级用途和结构提示，不能自动证明每一列的业务名称；列级解释仍需
表头、跨表目标和游戏样本共同验证。

## 一、总数据链

```text
道具 item_list
  ├── 类型 → item_type
  ├── 说明 → etc/text
  ├── 使用效果 → item_use
  │     ├── 宠物 → pet_list
  │     ├── 骑乘配置 → ride_list
  │     ├── 称号映射 → itemaddtitle → title_list
  │     ├── 风物志 → col_text / col_list
  │     ├── 随机礼包 → item_rand → 道具
  │     ├── 状态 → state_group → state_data
  │     └── 时装衣橱 → avatar_cupboard → equip_*
  └── 任务关系 → 轻量交换文件 → 外部任务站

宠物 pet_list
  ├── 角色／外形 → cha_list → cha_pic
  ├── 能力模板 → pet_model
  └── 骑乘配置 → ride_list → car_skill / skill_data_npc*

NPC / Boss cha_list
  ├── 战斗属性 → cha_fight
  ├── 外观 → cha_pic
  ├── 状态组 → state_group → state_data
  ├── 掉落组 → item_rand
  └── AI 选招 → cha_skill_choose / cha_skill_unit → skill_data_npc*

称号 title_list
  ├── 分组 → title_group
  └── 属性编号 → atb_fight
```

## 二、必须隔离的编号空间

相同数字出现在不同文件中，不代表同一实体。至少应分开保存以下编号空间：

| 编号空间 | 主文件 | 示例 |
| --- | --- | --- |
| 普通道具 | `item/item_list*.txt` | `item:13546` |
| 任务道具 | `quest/quest_item*.txt` | 与普通道具分开 |
| 宠物 | `pet/pet_list.txt` | `pet:1545` |
| 骑乘配置 | `object/ride_list.txt` | `ride:16` |
| 角色／怪物 | `object/cha_list.txt` | `cha:545` |
| 技能 | `skill/skill_data_*.txt` | 按技能表语境解释 |
| 状态组 | `skill/state_group.txt` | 组 ID `27477` |
| 状态数据 | `skill/state_data.txt` | 数据 ID `27477` |
| 称号 | `etc/title_list.txt` | `title:…` |
| 风物志 | `collection/col_list.txt` | `collection:…` |
| 时装衣橱 | `avatar_cupboard/avatar_cupboard.txt` | 衣橱记录 `216` |
| 外形配置 | `equip/equip_*.txt` | 帽子配置 `617` |
| 随机掉落组 | `item/item_rand.txt` | 掉落组 `932` |

已确认的错误案例是：`state_group` 的 `27477` 表示“霸体获取5”，并指向
`state_data:27984`；而 `state_data:27477` 是另一条“九天劫后章boss1”。绕过
状态组按同号直连会产生完全错误的 Boss 属性。

## 三、道具、说明与掉落

### `mb/item/item_list.txt`、`item_list2.txt`、`item_list3.txt`

官方索引名称为“道具列表”，是普通道具的主实体来源。三个分表处于同一普通
道具编号空间，来源优先级由项目配置控制，重复来源不会从原始层删除。

| 字段 | 含义 | 状态 |
| ---: | --- | --- |
| 1 | 物品 ID | 确认 |
| 2 | 物品名称 | 确认 |
| 3 | 物品类型 ID | 确认 |
| 5 | 道具图片／图标键 | 高可信 |
| 6 | 模型 ID | 确认；部分时装为空，不能作为衣橱外形的唯一来源 |
| 7 | 文字介绍 ID | 确认，连接 `mb/etc/text.txt` |
| 8 | 物品品质 | 确认；品质编号的玩家文案仍待完整核实 |
| 12 | 等级限制 | 确认；空值表示资料中没有等级限制 |
| 16 | 金钱类型 | 确认；`1` 表示流通金，否则按绑定金展示 |
| 17 | 购买价格 | 确认，基础单位为铜 |
| 18 | 售出价格 | 确认，基础单位为铜 |
| 31 | 使用属性 | 确认，保存效果 ID 与数量序列 |
| 35 | 堆叠上限 | 确认 |

注意：道具名称、说明、使用效果和类型是不同字段。页面应分别展示，不能把
`item_use` 的内部备注冒充道具说明。

### `mb/item/item_type.txt`

官方索引名称为“道具类型”。第 1 字段为类型 ID，第 2 字段为类型名称，后续
备注可用于解释类型用途。例如类型 `5` 的索引备注明确涉及骑宠和侍宠蛋。

### `mb/etc/text.txt`

官方索引名称为“客户端用文本”。第 1 字段为文本 ID，第 2 字段为正文。
`item_list` 第 7 字段稳定连接此表，用作道具说明。解析时需要：

- 去除 `<c:...>`、`<c>` 等颜色控制标签；
- 把文本中的 `\n` 转换为实际换行；
- 保留可读内容，不在页面增加“官方说明”前缀。

### `mb/item/item_use.txt`

官方索引名称为“道具使用属性”。

| 字段 | 含义 | 状态 |
| ---: | --- | --- |
| 1 | 使用效果 ID | 确认 |
| 2 | 一级使用类型 | 高可信，类型语义通过大量样本归纳 |
| 3–20 | 参数 | 未全部命名，必须按类型解释 |
| 21 | 内部／自然语言备注 | 确认；不一定等于完整玩家说明 |

已确认的重要连接：

| 使用类型 | 含义 | 连接 |
| ---: | --- | --- |
| 1 | 应用状态 | 参数 → `state_group` |
| 2 | 收录风物志 | 参数 → `collection/col_text.txt` |
| 9 | 开启普通随机礼包 | 参数 → `item_rand` |
| 27 | 增加角色经验 | 参数为经验值 |
| 28 | 获得宠物 | 参数 1 → `pet_list` 宠物 ID |
| 43 | 获得骑乘配置 | 参数 1 → `ride_list` 骑乘 ID |
| 56 | 应用状态数组 | 参数 → `etc/define_array.txt` → 状态组 |
| 141 | 开启猎魂／仙魄随机组 | `treasure_house_randgroup` → `randdata` → `card` |
| 145 | 激活战灵技能 | 参数 → `skill/skill_data_cmn.txt` |
| 176 | 解锁时装／外观 | 参数 1 → `avatar_cupboard` 衣橱记录 ID |
| 3 / 353 | 获得称号 | 参数 2 → `itemaddtitle` → `title_list` |

类型 `3` 是脚本调度入口。`537`、`1367`、`2139` 等二级编号不能直接当作
道具、掉落组或任务 ID；找不到稳定映射时只保留参数和备注。

### `mb/item/item_rand.txt`

官方索引名称为“道具随机掉落”，同时用于怪物掉落组和随机礼包内容。

| 字段 | 含义 | 状态 |
| ---: | --- | --- |
| 1 | 掉落组名称 | 确认 |
| 2 | 掉落组 ID | 确认 |
| 3–4 | 组控制字段 | 未完整确认 |
| 5 起 | `数量、道具 ID、概率值` 三元组重复 | 高可信 |

现有样本中概率值通常以 `1,000,000` 为基数，例如 `100` 对应配置值
`0.01%`、`450000` 对应 `45%`。这首先是**配置概率／权重**；最终是否独立
判定、固定抽一项或由服务端归一化，仍取决于游戏执行逻辑。

组内权重应检查合计。例如“跑环锦囊-京城”组 `378` 合计正好为 `100%`；
“跑环锦囊-茅山”组 `932` 合计为 `101%`，不能未经说明直接宣称为最终互斥
概率分布。

### `mb/item/item_pet.txt`

官方索引名称为“道具宠物列表”。第 2 字段可稳定命中普通道具 ID，用作
“道具产出宠物／骑乘配置”关系的补充证据。其余列尚不能对所有样本稳定解释；
当前仍有部分记录无法通过骑乘编号反查到宠物，不应用相似名称强行连接。

### `mb/item/item_mcht.txt`

官方索引名称为“商品道具”，保存商品／商城侧的道具配置。它不是普通道具
实体主表，引用到普通道具时仍应回到 `item_list*.txt` 获取名称和基础字段。
具体价格、货币和条件列尚未全部进入网站正式解析。

## 四、宠物、骑宠与坐骑技能

### `mb/pet/pet_list.txt`

官方索引名称为“宠物列表”，是 `pet:xxxx` 的主实体来源。

| 字段 | 含义 | 状态 |
| ---: | --- | --- |
| 1 | 宠物名称 | 确认 |
| 2 | 宠物 ID | 确认 |
| 3 | 角色 ID | 高可信，连接 `cha_list` |
| 5 | 模型编号 | 推测，正式字段名待确认 |
| 6 | 能力模板 ID | 高可信，连接 `pet_model` |
| 7 | 骑乘配置 ID | 确认，连接 `ride_list` |
| 9 | 策划／资料备注 | 推测 |

宠物名称相同不代表同一记录。例如梅花鹿同时存在 `pet:4` 和 `pet:1545`；
道具使用效果必须按明确的宠物 ID 连接，不能只按名称合并。

### `mb/pet/pet_model.txt`

官方索引名称为“宠物模板”。当前已确认／高可信字段：模板 ID，以及力量、
体魄、元神、筋骨四维值。`pet_list` 第 6 字段连接本表。

### `mb/pet/pet_list_group.txt`

官方索引名称为“宠物分组表”。用于把多个宠物 ID 组织到同一组，并提供组名
和图标。它不能替代 `pet_list` 的单体身份。

### `mb/pet/pet_text.txt`

官方索引名称为“宠物文本”，保存宠物系统相关的玩家文本或模板文本。当前
作为资料候选来源保留，尚未把所有文本稳定归到单一宠物记录。

### `mb/pet/pet_ability.txt`

官方索引名称为“宠物被动技能”。记录侍宠／骑宠能力配置，字段数量较多；
目前仅把它视为独立能力编号空间，不能把能力编号直接展示成玩家说明。

### `mb/pet/pet_newskill_list.txt`

官方索引名称为“圣兽9999技能新特性表”。属于新版宠物技能／特性配置，和
普通 NPC 技能、坐骑主动技能不是同一编号空间。

### `mb/pet/pet_fetter.txt`

官方索引名称为“宠物羁绊列表”。保存宠物羁绊组与成员／效果候选字段；尚未
完成全部字段的玩家化解释。

### `mb/pet/pet_catch.txt`

官方索引名称为“宠物捕捉难度”。用于捕捉系统，不应误当作宠物基础属性。

### `mb/object/ride_list.txt`

官方索引名称为“座骑列表”，是 `ride:xxxx` 的主实体来源。

| 字段 | 含义 | 状态 |
| ---: | --- | --- |
| 1 | 骑乘配置名称 | 确认 |
| 2 | 骑乘配置 ID | 确认 |
| 3 | 角色 ID | 高可信，连接 `cha_list` |
| 17–22 | 六个坐骑技能槽 | 确认 |
| 其余字段 | 动作、速度、人数、状态等候选配置 | 尚未完整确认 |

网站把宠物和独立骑乘配置合并到一个“宠物”标签页，但底层编号空间不合并。
已经被宠物引用的骑乘配置不重复显示为独立条目。

### `mb/object/ride_connection.txt`

官方索引名称为“座骑的每个单位连接”。用于多单位／多人骑乘部件连接，和
`ride_list` 的主配置不同。字段方向仍需更多样本验证。

### `mb/object/ride_merge.txt`

官方索引名称为“坐骑合并表”。用于坐骑配置合并候选关系，当前尚未作为
宠物身份关系的主证据。

### `mb/pet/car_skill.txt`

官方索引明确为“坐骑技能表”。

| 字段 | 含义 | 状态 |
| ---: | --- | --- |
| 1 | 技能名称 | 确认 |
| 2 | 技能 ID | 确认，被 `ride_list` 六个技能槽引用 |
| 3–4 | 数值参数 | 未知单位 |
| 5 | 内部备注 | 确认，但不一定是玩家效果说明 |

坐骑技能名称和内部备注优先来自本表；完整技能说明和图标再从
`skill_data_npc*.txt` 补充。空技能槽不得虚构技能，页面序号应按实际非空槽
连续显示。

### 宠物／骑宠获得链示例

```text
跑环锦囊-京城（item_rand:378）
  → item:13546 梅花鹿
  → item_list 第 31 字段：效果 910
  → item_use:910，类型 28，参数 pet:1545
  → pet:1545 梅花鹿
  → pet_list 第 7 字段：ride:16
  → ride:16 梅花鹿
  → 技能 6369 冰箭、6370 回春
```

这条链说明 `item:13546`、`pet:1545`、`ride:16` 和 `cha:545` 是四个不同
编号空间中的相关记录。

## 五、角色、怪物、Boss 与战斗配置

### `mb/object/cha_list.txt`

官方索引名称为“cha列表”，是 NPC、怪物、Boss、宠物外形角色等 `cha` 记录
的主表。当前确认的重要连接：

| 字段 | 含义 | 状态 |
| ---: | --- | --- |
| 2 | 角色记录 ID | 确认 |
| 5 | 战斗属性 ID | 确认，连接 `cha_fight` |
| 6 | 外观 ID | 确认，连接 `cha_pic` |
| 14 | 附加状态组 ID 列表 | 确认，`*` 分隔 |
| 19 | 掉落组 ID 列表 | 确认，`*` 分隔，开头 `0` 为空值 |

第 20 字段在部分样本中也能命中“等级世界掉落”等 `item_rand` 记录，但其正式
业务语义尚未写成通用规则，应与第 19 字段分开保留。

### `mb/object/cha_fight.txt`

官方索引名称为“cha战斗相关属性”。通过龟丞相样本已确认：

| 字段 | 含义 |
| ---: | --- |
| 1 | 战斗属性 ID |
| 2 | 等级 |
| 9 | 基础生命 |
| 26 | 最终生命；当前样本满足 `字段9 + 字段6 × 10` |
| 29 | 物理／普通伤害 |
| 31 | 状态加成前物理防御 |
| 33 | 状态加成前法术抗性 |
| 40 | 抵抗会心几率 |
| 50 | 综合评分／战力 |

未列出的字段不能仅凭数值形态命名。

### `mb/object/cha_pic.txt`

官方索引名称为“cha图片”。当前已确认：第 2 字段是外观 ID，第 3 字段为
角色模型配置路径，第 5 字段是模型缩放倍率。`cha_list` 第 6 字段连接本表。

### `mb/object/cha_skill_choose.txt`

官方索引名称为“NPC技能选择”。保存 NPC／Boss 的选招配置、阶段条件与技能
候选。例如黄四爷在不同血量或条件下的技能选择可从本表继续关联 NPC 技能表。
具体条件字段必须结合 `cha_skill_unit` 和实战样本解释。

### `mb/object/cha_skill_unit.txt`

官方索引名称为“NPC技能单元”。保存选招单元内的技能权重／组合候选，是
`cha_skill_choose` 和具体技能 ID 之间的辅助层。不能把权重数字当作技能 ID。

### `mb/object/cha_sound.txt` 与 `mb/etc/sound_list.txt`

`cha_sound` 官方索引名称为“NPC音效表”，`sound_list` 为“声音列表”。前者
把角色音效槽关联到声音编号，后者保存声音资源候选。当前网站尚未公开完整音效
资源链。

## 六、状态、技能与职业学习

### `mb/skill/state_group.txt`

官方索引名称为“状态组”。第 2 字段为状态组 ID，第 4 字段保存实际状态数据
ID 列表。角色、道具和技能通常先引用状态组。

### `mb/skill/state_data.txt`

官方索引名称为“状态数据”。第 2 字段为状态数据 ID；第 9 字段在已确认样本中
按以下三元组重复：

```text
修改模式 * 属性 ID * 数值
```

- 模式 `0`：固定值；
- 模式 `1`：百分比，原始整数除以 `100` 后为页面百分数；
- 负数表示降低；
- 多个百分比来源先相加，再作用于基础值。

正确连接必须是：

```text
引用方状态组 ID
  → state_group 第 2 字段
  → state_group 第 4 字段的状态数据 ID
  → state_data 第 2 字段
```

### `mb/skill/skill_data_npc*.txt`

官方索引分别称为“技能组属性（NPC）”“NPC1”“NPC2”“NPC3”“NPC4”等。
当前确认字段：

| 字段 | 含义 |
| ---: | --- |
| 1 | 技能名称 |
| 2 | 技能 ID |
| 4 | 图标键，高可信 |
| 5 | 玩家可读技能说明 |

`skill_data_npc_pet*.txt` 是 PET 技能组属性分表。多个分表可能存在同号版本，
必须保留来源优先级和原始来源，不能随意跨版本覆盖。

### `mb/skill/skill_learn.txt`

官方索引名称为“技能学习”。保存技能学习侧的等级、花费、前置或其他条件候选；
具体参数并未全部确认。修改本地记录只可能影响客户端显示，服务端仍可拒绝学习。

### `mb/skill/npc_teach_skill.txt`

官方索引名称为“导师技能模板”。用于导师界面可展示／可选择的技能模板候选，
不是服务端授予权限的唯一来源。

### `mb/sec_char/faculty_skills.txt`

官方索引名称为“职业技能表”。用于职业与技能集合的关系。职业技能学习链通常
需要同时检查：

```text
职业技能集合 faculty_skills
  + 学习条件 skill_learn
  + 导师模板 npc_teach_skill
  + 技能本体 skill_data_*
```

客户端本地修改不能绕过服务端的职业、状态、等级或导师校验。

### `mb/etc/define_array.txt`

官方索引名称为“数组定义”。道具使用类型 `56` 等会先引用数组定义，再由数组
中的编号连接多个状态组。数组编号和状态组编号必须分开。

## 七、称号与属性加成

### `mb/etc/title_list.txt`

官方索引名称为“称号列表”。

| 字段 | 含义 | 状态 |
| ---: | --- | --- |
| 1 | 称号名称 | 确认 |
| 2 | 称号 ID | 确认 |
| 3 | 称号分组 ID | 确认，连接 `title_group` |
| 6 | 佩戴后生效的主动属性串 | 确认 |
| 8 | 称号说明 | 确认 |
| 9 | 获得条件 | 确认 |
| 11 | 获得后生效的被动属性串 | 确认 |

称号属性串按“属性 ID、数值形式、数值”三元组排列，属性 ID 连接
`etc/atb_fight.txt`。

### `mb/etc/title_group.txt`

官方索引名称为“称号组”。用于称号检索分组。第 3 字段的 `1–10` 在现有资料中
稳定形成上级族群，但原文件没有提供这些族群的正式中文名称；网站上的上级分类
名称是资料库归纳，不应冒充官方字段。

### `mb/etc/atb_fight.txt`

官方索引名称为“属性定义（战斗相关数据）”。保存属性 ID 与属性名称，是称号
主动／被动属性及其他属性三元组的解释字典。

### `mb/etc/itemaddtitle.txt`

官方索引名称为“道具加称号”。第 2 字段为被道具使用效果引用的映射 ID，
第 4 字段为称号 ID。完整获得链为：

```text
item_list 使用效果
  → item_use 类型 3 / 二级 353
  → itemaddtitle 映射 ID
  → title_list 称号 ID
```

### `mb/etc/title_share.txt`

官方索引名称为“称号共享表”。用于称号共享候选关系，字段语义尚未完整解析，
不作为称号分组的替代来源。

## 九、时装衣橱与装备美术资源

### `mb/avatar_cupboard/avatar_cupboard.txt`

官方索引名称为“时装橱柜”。现有样本确认：

| 字段 | 含义 |
| ---: | --- |
| 1 | 衣橱显示名称 |
| 2 | 衣橱记录 ID |
| 3 | 对应普通道具 ID |
| 4 | 外形配置编号 |
| 5 | 时装道具类型 |
| 6 | 性别：`1` 男、`2` 女，其他值需单独解释 |

道具使用类型 `176` 的参数连接衣橱记录 ID。时装道具的 `item_list` 模型 ID
并不总是权威：当前样本中存在道具模型字段为空、但衣橱第 4 字段有有效外形的
记录，也存在两处编号不一致。因此衣橱展示应优先使用衣橱表，缺失时再回退道具表。

### `mb/avatar_cupboard/avatar_cupboard_group.txt`

官方索引名称为“时装橱柜组”。包含收集数量阶段和主题套组，部分主题组保存
衣橱记录 ID 列表及属性奖励串。

### `mb/avatar_cupboard/avatar_cupboard_effect.txt`

官方索引名称为“时装橱柜-技能特效”。当前资料仅有少量特效记录，不能用来
替代常规时装外形配置。

### `mb/equip/equip_*.txt`

官方索引给出的装备串表：

| 文件 | 含义 |
| --- | --- |
| `equip/equip_mz.txt` | 帽子装备串 |
| `equip/equip_yf.txt` | 衣服装备串 |
| `equip/equip_xz.txt` | 鞋子装备串 |
| `equip/equip_kz.txt` | 裤子装备串 |
| `equip/equip_yd.txt` | 腰带装备串 |
| `equip/equip_wq.txt` | 武器装备串 |
| `equip/equip_fb.txt` | 法宝装备串 |
| `equip/equip_chy.txt` | 衬衣装备串 |

对于时装帽子、外衣和鞋子，`avatar_cupboard`／`item_list` 的外形配置编号会
分别进入 `equip_mz`、`equip_yf`、`equip_xz`。配置表中通常包含男、女资源串。

相同外形配置编号被男女款、绑定款或限时款复用是正常现象。在线角色穿戴状态
还可能由服务端直接下发外形配置编号；修改本地道具或衣橱的引用，不一定改变
服务器已经下发的外形。若用于纯本地美术替换，应明确评估修改装备串记录会影响
所有复用该配置编号的道具。

## 十、任务道具与外部任务库

### `mb/quest/quest_item.txt`

官方索引名称为“任务道具”，是任务逻辑道具的主来源。第 1 字段为名称，第 2

### `mb/quest/quest_item_ex.txt`

官方索引名称为“任务道具扩展”。它与 `quest_item` 的覆盖／扩展关系尚未全部
确认，不能无条件覆盖主记录。

### `mb/quest/quest_item_mapping.txt`

官方索引名称为“任务道具与实际道具的映射关系”。用于任务逻辑道具与普通
道具的候选映射，必须同时保留两端的资源类型。

### `mb/quest/quest_text.txt`

官方索引名称为“任务文本”，保存任务对话、目标、完成文本等。本站不复制现有
任务数据库；任务项目通过轻量交换文件提供任务 ID、名称、关系类型、数量和站内
路径，本项目只验证目标资源并外链到任务站。

## 十一、文件来源与展示规则

1. `original_data/` 始终只读，不直接修补原始文件；
2. 所有解析保留 `source_file`、`source_row`、原始行和构建 ID；
3. 控制标签、颜色标签和字面 `\n` 在展示层清洗，原始层保持不变；
4. 页面不显示无助于访问者理解的内部来源行号，但数据库仍保留追溯信息；
5. 原始明确关系标记 `source`，映射表关系标记 `mapped`，人工核实标记
   `curated`，名称推测标记 `inferred`；
6. 推测关系默认不冒充正式事实；
7. 线上数据库只包含查询所需的规范化索引和压缩详情，不上传完整原始资料；
8. 本地配置可能是服务端配置的镜像或客户端展示资料，不能据此断言客户端拥有
   掉落、学习、发奖或角色持久化的最终决定权。

## 十二、尚待确认的重点

- `pet_list` 的角色、模型及宠物种类列的正式字段依据；
- `ride_list` 除六个技能槽外的速度、人数、动作和状态字段；
- `ride_connection` 与多单位坐骑的完整连接方向；
- `pet_ability`、`pet_newskill_list` 和 `pet_fetter` 的完整玩家语义；
- `item_use` 所有一级类型及多态参数的完整定义；
- `item_rand` 第 3–4 字段及服务端最终随机算法；
- `cha_fight` 尚未验证字段的正式属性名；
- `cha_skill_choose` 与 `cha_skill_unit` 的全部条件和权重单位；
- `skill_learn`、`npc_teach_skill` 的客户端展示条件与服务端校验边界；
- `title_group` 上级族群的官方名称；
- `item_list` 品质编号的完整官方名称；
- 时装、普通装备与服务端下发外形配置的最终优先级；
- 脚本礼包、活动奖励、统一掉落等未在现有客户端表中展开的服务端规则。
